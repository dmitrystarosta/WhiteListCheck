## Состав v0.5.1 (что вошло)

Мелкий, но настоящий багфикс — сову на глобус не натягивали.

- **Синхронизация виджета и экрана.** Виджет и фоновый воркер пишут
  вердикт в SharedPreferences и перерисовывают виджет, но экран
  приложения (детальные карточки живут в памяти, в ScanState) об этом
  не знал. Баг ловится так: в приложении «всё в норме» → авиарежим →
  тап по виджету даёт «нет сети» (виджет сереет) → открываем приложение
  по иконке, а там всё ещё «всё в норме».
- **Решение:** в ScanState добавлено поле `checkedAt` (время получения
  показанного результата; пишется в обеих ветках runScan — и «нет сети»,
  и обычной — одним `now` вместе с last_check_ts). На событие ON_RESUME
  (DisposableEffect + LifecycleEventObserver в MainScreen) сверяем
  last_check_ts из prefs с state.checkedAt: если снаружи проверка
  НОВЕЕ И вердикт ОТЛИЧАЕТСЯ — молча вызываем runScan(). Совпадающий
  вердикт не пересканируем (лишний скан ни к чему).
- Побочный плюс: после фоновой смены режима открытие приложения тоже
  само подтягивает актуальный результат.
- **ВАЖНО:** LocalLifecycleOwner берётся из androidx.compose.ui.platform
  (в Compose 1.6.x / BOM 2024.06.00 ещё не deprecated; в 1.7+ переехал
  в androidx.lifecycle.compose — поправить импорт при обновлении BOM).

## Состав v0.5.3 (что вошло)

Релиз «первое впечатление и удержание»: онбординг, помощь с фоном, отзыв.
Ядро проверки не трогали — только новые экраны и полировка.

- **Онбординг первого запуска** (OnboardingFlow → OnboardingWelcome +
  ConnectivityHelpScreen). Экран 1: приветствие (логотип-марка по центру +
  название) + ненавязчивое предложение «Фоновая проверка и уведомления»
  («Включить» / «Позже»). «Включить» включает фон (bg_enabled +
  scheduleBackground) и ведёт на экран 2; «Позже» — сразу на главный.
  Экран 2 «Как остаться на связи»: кнопка «Разрешить» (POST_NOTIFICATIONS)
  со статусом «✓ Разрешено» + кнопка «Открыть настройки» (батарея/автозапуск).
- **Разрешение запрашивается ТОЛЬКО на экране 2.** Раньше экран 1 сам
  вызывал системный диалог, а экран 2 проверял статус до ответа → висела
  «Разрешить», хотя разрешение уже дано. Исправлено: один источник запроса.
- **Показ онбординга — по времени установки, НЕ по SharedPreferences.**
  freshInstall = (firstInstallTime == lastUpdateTime) + флаг onboarded.
  Причина: системный бэкап Android при переустановке восстанавливает prefs
  (bg_enabled/last_verdict), и проверка «свежести» по prefs ложно пропускала
  онбординг. Обновившимся (не чистая установка) он не показывается.
  Проверено на MIUI: чистая установка → онбординг; «Позже» ведёт на главный;
  после «Разрешить» статус меняется на «Разрешено».
- **Экран «Как остаться на связи» переоткрывается из подвала** (та же
  ConnectivityHelpScreen, showBack=true). Кнопка батареи/автозапуска —
  ACTION_APPLICATION_DETAILS_SETTINGS (fallback ACTION_SETTINGS), БЕЗ
  спец-разрешения (Play не придерётся, манифест не меняли — POST_NOTIFICATIONS
  уже был). На всех прошивках ведёт на страницу приложения; на MIUI там есть
  «Автозапуск» и «Батарея», на стоковом Android — только «Батарея».
  Автозапуск MIUI прочитать нельзя (нет API) → кнопка-действие, а не статус
  «Настроено»; батарею читать можно (PowerManager.isIgnoringBatteryOptimizations)
  — отложено до отзывов.
- **Блок «в приложении нет рекламы» в подвале** (ReviewCard): текст + две
  одинаковые по форме кнопки-логотипа. RuStore (res/drawable/ic_rustore.xml,
  официальная синяя иконка из брендбука, Image без тонировки) → RUSTORE_URL;

- **Полировка подвала:** отступ над карточкой отзыва (отделяет футер от

## Состав v0.5.2 (что вошло)

Полировочный релиз: одна видимая мелочь (логотип) и два багфикса из
живого использования на ТВ и телефоне, плюс смена ссылки в «Поделиться».

- **Логотип-знак в подвале + ссылка на сайт.** Над копирайтом по центру —
  векторный знак «уши+глобус» БЕЗ плитки-фона, нарисован в Canvas
  (composable `AppLogoMark`): круги ушей и глобуса заливаются цветом ФОНА
  экрана (поэтому нижние дуги ушей корректно перекрываются глобусом, видны
  только линии), линии — цветом `primary` из темы. Знак адаптивный:
  коричневые линии на светлой теме, светло-бежевые на тёмной. Тап открывает
  belyjspisok.ru (константа `SITE_URL`). Размер 52dp (видимый знак ~40dp +
  зона нажатия). Отдельного XML-ассета нет (в отличие от иконки-плитки,
  которую пробовали ранее и отклонили). На ТВ знак стал фокусируемым —
  в подвале теперь ДВЕ цели: логотип → сайт, «Версия…» → страница релизов.
  Проверено: телефон (светлая и тёмная), ТВ (тёмная).

- **Стабильные раскрывашки (фикс сворачивания).** Флаги «развёрнуто» чипа
  «Сеть», сноски «Почему ошибки разные» и трёх карточек групп ПОДНЯТЫ на
  уровень MainScreen (`netExpanded`, `whyExpanded`, `expA`/`expB`/`expC`),
  а не хранятся внутри элементов LazyColumn. Причина: уехавший за нижний
  край элемент LazyColumn уничтожается вместе с состоянием, и rememberSaveable
  внутри него восстанавливался неодинаково — на ТВ блок сворачивался сразу
  при прокрутке за экран, на телефоне слетал после выхода-возврата в
  приложение. Чип сети «держался» лишь потому, что он первый элемент списка
  и почти не уезжает. Композаблы NetworkChip / GroupCard / Footnote теперь
  получают состояние снаружи (`expanded` + `onToggle`). netExpanded
  по-прежнему ключуется типом сети (при смене сети сворачивается).
  ВАЖНО: не возвращать эти флаги внутрь композаблов. Граница: заход в
  «Списки сайтов» и возврат по-прежнему сбрасывает раскрывашки (MainScreen
  покидает композицию) — это не регресс; если понадобится, поднять флаги
  до уровня App. Проверено: ТВ-прокрутка и выход-возврат сохраняют состояние.

- **Ссылка в «Поделиться» → сайт.** В тексте кнопки «Поделиться вердиктом»
  вместо длинной ссылки на RuStore теперь `SITE_URL` (belyjspisok.ru):
  сайт и объясняет приложение, и ведёт на все магазины. Константа
  RUSTORE_URL оставлена в коде (нигде не используется, но пусть лежит).

  виджет-проверки). Обновление виджета: после каждой проверки,

  снимок, относительный счётчик сам не «тикает», ему нужна перерисовка
  каждую минуту, а MIUI такие фоновые обновления душит → счётчик вечно
  висел на «сейчас». Абсолютные часы верны без единого обновления.
  До первой проверки — «нажмите». НЕ возвращать относительный счётчик.
- Устаревание: >60 мин → setImageAlpha 130 + янтарное время #FFD180.
- **ТАП ПО ВИДЖЕТУ = ПРОВЕРКА** (не открытие приложения): широковещалка
  самому себе StatusWidget.ACTION_WIDGET_SCAN → onReceive →
  showChecking() (крутящийся ProgressBar на месте подписи; свой drawable
  в RemoteViews анимировать нельзя, только штатный indeterminate) +
  OneTimeWork WidgetScanWorker БЕЗ сетевого constraint (иначе при
  отсутствии сети спиннер крутился бы вечно — воркер сам быстро вернёт
  «нет сети»). WidgetScanWorker уведомлений НЕ шлёт (пользователь и так
  смотрит на виджет) и всегда пишет результат + время + обновляет
  виджет, включая «нет сети».
- **ФИКС «открывалось сброшенным»:** PendingIntent уведомления теперь
  через packageManager.getLaunchIntentForPackage (ACTION_MAIN/LAUNCHER +
  RESET_TASK_IF_NEEDED) — поднимает существующую задачу как иконка,
  результаты сохраняются. Прямой Intent(MainActivity) этого не давал.
- ГРАБЛИ: при создании файлов через GitHub web путь вводить БЕЗ
  markdown-звёздочек (папка «**layout**» ломала сборку).

## Решённые вопросы дизайна (не переоткрывать без причины)

- **Двухзонный тап по виджету — РЕШЕНО: НЕ ДЕЛАЕМ** (22.07.2026).
  Была идея: верх (логотип) открывает приложение, низ (время) запускает
  проверку. Отказались: на 1×1 подпись времени — крохотная мишень, зоны
  ничем не обозначены (скрытый UI), «тап по времени = открыть» —
  неинтуитивно, а открытие и так есть по иконке рядом. Решение владельца:
  «пусть сперва привыкнут к 1×1». Вернуться к идее имеет смысл только
  на увеличенном виджете (2×1 и больше), и тогда большую зону логичнее
  отдать проверке, мелкую — открытию.

## Известные проблемы и особенности

- **VPN на роутере не определяется** — системное ограничение Android
  (для устройства это обычный Wi-Fi), НЕ баг. Вердикт при этом всё
  равно покажет «похоже, включён VPN» по доступности сайтов.
- **ТВ: кнопка сброса списков прилипает к нижнему краю экрана** —
  прокрутка на ТВ следует за фокусом. Косметика; чистого решения без
  экспериментальных API нет. Отложено.
- Версии до 0.3.1 невидимы в лаунчере Android TV — удалять через
  Настройки → Приложения → Показать все приложения.
- MIUI может убивать фоновый воркер без ручных разрешений (Автозапуск +
  снятие ограничений батареи). С v0.5.3 есть внутренняя подсказка «Как
  остаться на связи» с переходом в настройки приложения, но тумблеры
  включает сам пользователь (статус автозапуска MIUI прочитать нельзя).
- Интервал фоновой проверки нестрогий (15+ мин).
- На старых устройствах возможны TLS-ошибки отдельных сайтов
  (сертификаты) — пояснение в сноске.
- Инцидент безопасности (закрыт): первый release-ключ скомпрометирован,
  перевыпущен 06.07.2026.
